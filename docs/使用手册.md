# am-history-importer 使用手册

把本机 **Codex** / **Cursor** 聊天历史，一次性导入到远程 [Agent Memory](https://github.com/rohitg00/agentmemory)。  
已导入过的会话会跳过（本机 checkpoint），可重复安全执行。

> Claude Code 请用官方 `import-jsonl`，本工具不覆盖。

---

## 1. 安装

需要 **Node.js 22+**、**pnpm**。

```bash
git clone https://github.com/andrew05060414/am-history-importer.git
cd am-history-importer
pnpm install
pnpm build
```

之后都用：

```bash
node dist/cli.js <命令>
```

---

## 2. 配置（一次即可）

编辑 `~/.agentmemory/.env`（Windows：`C:\Users\<你>\.agentmemory\.env`）：

```env
# 日常 hooks / MCP / Cursor 连接（外出可用 Tailscale）
AGENTMEMORY_URL=http://100.73.230.28:3111

# 仅本导入工具使用（在家建议局域网，更快、少超时）
AGENTMEMORY_URL_LOCAL=http://192.168.0.102:3111

AGENTMEMORY_SECRET=<NAS 上 data/.hmac 的内容>
```

| 变量 | 谁用 |
|------|------|
| `AGENTMEMORY_URL` | 日常 Agent 连记忆 |
| `AGENTMEMORY_URL_LOCAL` | **只有** `am-history-importer` 批量导入 |
| `AGENTMEMORY_SECRET` | Bearer 密钥 |

首次运行还会生成 `~/.agentmemory/history-importer/config.json`（一般不用手改）。

探活（可选）：

```bash
curl -fsS http://192.168.0.102:3111/agentmemory/livez
```

## 3. 推荐用法（三步）

### ① 先看本机有多少可导（不写 NAS）

```bash
node dist/cli.js discover --limit 20
```

### ② 小批量试水

```bash
node dist/cli.js sync --source codex --limit 5 --concurrency 4
node dist/cli.js sync --source cursor --limit 5 --concurrency 4
```

到 Agent Memory Viewer 搜一下刚导的话题，确认能搜到。

### ③ 全量导入

```bash
# 在家：会自动走 AGENTMEMORY_URL_LOCAL
node dist/cli.js sync --concurrency 4
```

启动日志应类似：

```text
agentmemory: http://192.168.0.102:3111 (AGENTMEMORY_URL_LOCAL / LAN)
hooks/MCP stay on: http://100.73.230.28:3111
writing N session(s) ... (concurrency=4, timeout=until done)
```

跑完看汇总：`synced` / `skipped` / `failed`。  
再跑一次同一条命令，应接近：`synced=0, skipped=N`。

查看进度库：

```bash
node dist/cli.js status
```

## 4. 常用命令

| 命令 | 作用 |
|------|------|
| `discover` | 只扫描列表，不写入 |
| `sync` | 真正导入 |
| `status` | 看本机 checkpoint 已导多少 |

| 参数 | 作用 |
|------|------|
| `--source codex` / `cursor` | 只导一端 |
| `--limit N` | 最多 N 个会话（试水用） |
| `--concurrency N` | 同时写几个会话（默认 8；NAS 吃力用 2～4） |
| `--input PATH` | 指定 zip / 目录 / `state.vscdb` / snapshot |
| `--timeout-ms N` | 单次 HTTP 超时；**默认 0 = 等到传完** |
| `--dry-run` | 解析 + 对照 checkpoint，不写 NAS |

### 指定输入示例

```bash
# cockpit 导出的 Codex zip
node dist/cli.js sync --input path/to/codex-session-export.zip

# cursaves 快照目录
node dist/cli.js sync --input ~/.cursaves/snapshots

# 直接读 Cursor 库（可开着 Cursor）
node dist/cli.js sync --source cursor --input ~/AppData/Roaming/Cursor/User/globalStorage/state.vscdb
```

## 5. 运行时你会看到什么

- `… codex:<id> 500/2000 observations` — 长会话进度，正常  
- `retry 1/3 POST ... → 504` — NAS/网关忙，自动重试，多数会继续  
- `synced ... obs=1234` — 该会话完成并记入 checkpoint  
- `failed ...` — 该会话失败；修好网络/降并发后再 `sync` 会重试（已成功的会 skip）

Codex / Cursor **开着也可以导入**。

## 7. 常见问题

**Q: 改了 `.env` 仍显示 Tailscale？**  
A: 看是否设了 `AGENTMEMORY_URL_LOCAL`。导入优先 LOCAL。启动行里的 `agentmemory:` 才是实际地址。

**Q: 很多 504？**  
A: 用 `--concurrency 2`，再跑一次即可。根因多半是 NAS 负载或反向代理超时。

**Q: 会重复导入吗？**  
A: 同一会话内容没变会 skip。失败未记 checkpoint 的会重试。

**Q: Claude 历史？**  
A: 官方 `npx @agentmemory/agentmemory import-jsonl`（注意容器内路径 / inbox）。

**Q: 协议是 SSH 吗？**  
A: 不是。就是本机 → `http://NAS:3111` 的 REST（HTTP over TCP）。

## 8. 数据读哪里、写哪里

| 源 | 默认扫描 |
|----|----------|
| Codex | `~/.codex/sessions/**/rollout-*.jsonl`、`archived_sessions`；也支持 cockpit zip |
| Cursor | `~/.cursaves/snapshots/**/*.json.gz`；或 Cursor `state.vscdb` |

写入 Agent Memory 的会话 ID：`import-codex-<uuid>` / `import-cursor-<composerId>`。  
本机去重库：`~/.agentmemory/history-importer/checkpoint.db`。
